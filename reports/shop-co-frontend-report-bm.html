Frontend Itu Apa?

Jawapan paling mudah: frontend ialah bahagian kedai yang pelanggan nampak. Ia seperti rak produk, papan harga, troli, kaunter, dan resit. Backend pula ialah bilik pekerja di belakang kedai.

Ringkasan satu pandangan

Pelanggan nampak

Produk, harga, pilihan cetakan, troli, checkout, profil, pesanan, fail artwork, chat, dan tracking.

Frontend buat

Ambil klik pengguna, simpan pilihan sementara, panggil API backend, dan tunjuk jawapan kepada pengguna.

Masalah utama

Produk yang dipaparkan dan troli utama belum bersambung dengan sempurna kepada proses pesanan backend.

Graf ini ialah gambaran mudah berdasarkan semakan kod, bukan ukuran prestasi pengguna secara langsung.

Perkara paling penting: pelanggan boleh nampak produk dan memasukkannya ke troli, tetapi produk prod- disimpan dalam pelayar sahaja. Backend membaca troli pangkalan data. Jadi pesanan boleh gagal walaupun troli nampak berisi.

Ciri Dan Mekanik

Apa Yang Frontend Boleh Buat?

Ciri pelanggan

  • Lihat halaman utama, kategori, dan produk.
  • Cari dan tapis produk.
  • Pilih bahan, saiz, finishing, kuantiti, dan tempoh siap.
  • Daftar, log masuk, dan urus profil.
  • Tambah produk ke troli dan buka checkout.
  • Upload artwork terus ke S3.
  • Lihat sejarah pesanan, komen, chat, dan tracking.

Ciri pekerja

  • Dashboard admin untuk pesanan dan tugasan.
  • Urus artwork, design, production, dan packaging.
  • Lihat pengguna, chat, penghantaran, dan status server.
  • Aplikasi admin mudah alih menggunakan Expo.
  • Versi desktop menggunakan Electron.

Mekanik frontend dalam 4 langkah

1Pengguna klikContoh: tekan “Tambah ke troli”.
2React bertindakSkrin membaca pilihan dan menjalankan fungsi.
3Frontend minta dataAxios menghantar permintaan kepada API backend.
4Skrin dikemas kiniReact Query menyimpan jawapan dan memaparkannya.

Worktree / Pokok Sistem

Fail Frontend Duduk Di Mana?

Rajah pokok ini menunjukkan tempat utama dalam projek. Fikirkan setiap folder sebagai sebuah laci yang menyimpan jenis barang tertentu.

frontend/ |-- src/app/ # halaman yang pengguna buka | |-- page.tsx # halaman utama | |-- home/shop/ # senarai dan detail produk | |-- home/cart/ # troli dan checkout | |-- home/profile/ # profil, pesanan, upload | `-- rsvp/ # jemputan RSVP |-- src/components/ # bahagian kecil skrin | |-- global/ # nav, footer, chat, progress | |-- forms/ # borang login dan alamat | `-- page-sections/ # blok untuk setiap halaman |-- src/hooks/ # logik ambil dan ubah data |-- src/api/ # alamat panggilan ke backend |-- src/store/ # keadaan UI sementara |-- src/constants/ # data tetap dan produk dummy |-- src/types/ # bentuk data TypeScript `-- package.json # senarai teknologi dan arahan

Contoh: halaman produk

  1. Fail dalam app/home/shop/[id] membuka halaman.
  2. Komponen product-details.tsx melukis pilihan produk.
  3. Hook useProducts.ts mencari data produk.
  4. Apabila troli digunakan, api/cart.ts menentukan sama ada data pergi ke backend atau localStorage.
Di sinilah masalah berlaku: useProducts.ts memaksa katalog dummy untuk dipaparkan. api/cart.ts menyimpan produk dummy dalam pelayar. Proses checkout backend tidak membaca tempat simpanan itu.

Masalahnya: backend mempunyai lebih banyak status seperti artwork, design, pembetulan, printing, dan packaging. Frontend belum menunjukkan semua status ini dengan betul.

Cara guna, langkah demi langkah

  1. Buka https://studioivory.art/.
  2. Tekan Shop. Cari produk yang diperlukan.
  3. Buka produk. Pilih bahan, saiz, pilihan tambahan, dan kuantiti.
  4. Log masuk. Tekan Add to cart.
  5. Buka troli. Pastikan produk dan kuantiti betul.
  6. Tekan checkout. Isi nama dan alamat penghantaran Malaysia.
  7. Hantar pesanan. Kaedah web sekarang ialah COD.
  8. Buka Profile > Upload. Pilih pesanan dan upload artwork.
  9. Buka Profile > Orders untuk melihat komen dan tracking.
Amaran sekarang: langkah 7 mungkin gagal untuk produk katalog dummy. Troli yang kelihatan berisi pada skrin tidak semestinya berisi dalam backend.

Apa Yang Rosak Atau Belum Siap?

TahapMasalahPenerangan paling mudah
KritikalTroli tidak sampai ke backendProduk dummy duduk dalam pelayar. Backend mencari produk dalam pangkalan data. Kedua-duanya melihat tempat yang berbeza.
KritikalPilihan dan harga hilangHarga terperinci dikira pada skrin, tetapi semua pilihan cetakan tidak dihantar sebagai data pesanan yang lengkap.
TinggiProgress salahStatus SHIPPED dan DELIVERED ditanda lambat satu langkah. CANCELLED juga boleh kelihatan seperti semua langkah berjaya.
TinggiSaiz menjadi teks pelikFrontend mencantumkan pilihan design ke dalam saiz. Backend kemudian gagal mencari saiz itu dalam stok.
SederhanaBayaran mengelirukanHalaman bayaran menyebut kad, FPX, dan e-wallet, tetapi checkout sebenar menggunakan COD.
SederhanaKesalahan troli disembunyikanJika API gagal, skrin masih boleh menunjukkan data lokal dan melaporkan tindakan berjaya.
SederhanaSocket pelanggan tidak dipasangKod kemas kini masa nyata ada, tetapi providernya tidak digunakan pada akar aplikasi.
SederhanaFilter dan pautan tidak lengkapFilter material/turnaround tidak digunakan. Beberapa pautan menuju halaman yang tiada.
SederhanaAlamat boleh salahPilihan guna alamat profil boleh meletakkan nama negeri di ruang alamat penuh.
SederhanaRalat TypeScript diabaikanBuild production dibenarkan walaupun TypeScript menemui ralat.

Apa perlu dibuat selepas ini?

  1. Paling awal: pindahkan katalog aktif ke backend atau hantar data konfigurasi yang lengkap kepada backend.
  2. Gunakan satu troli sahaja. Jangan campurkan localStorage dan troli pangkalan data.
  3. Simpan pilihan material, saiz, design, finishing, turnaround, kuantiti, dan harga sebagai medan berasingan.
  4. Tunjukkan semua status artwork, design, printing, packaging, dan delivery kepada pelanggan.
  5. Tambah ujian automatik dari pilih produk sehingga pesanan berjaya dibuat.
Kesimpulan mudah: rupa dan ciri frontend sudah banyak. Masalah terbesar bukan pada kecantikan skrin. Masalah terbesar ialah data produk dan troli belum mengalir dengan betul ke backend.

Mula Di Sini

Backend Itu Apa?

Jawapan paling mudah: backend ialah bilik operasi di belakang kedai. Pelanggan tidak nampak bilik ini. Di sinilah pekerja menyemak akaun, membaca troli, menyimpan pesanan, mengurus fail, dan menghubungi syarikat penghantaran.

Ringkasan satu pandangan

Backend terima

Permintaan daripada frontend seperti login, tambah troli, buat pesanan, upload fail, atau lihat tracking.

Backend buat

Semak kebenaran, jalankan peraturan, simpan data, hantar notifikasi, dan pulangkan jawapan.

Backend simpan

Pengguna, produk, troli, pesanan, tugasan, fail, parcel, chat, dan log audit.

Ciri Dan Mekanik

Apa Yang Backend Boleh Buat?

Operasi kedai

  • Daftar, login, token, profil, dan peranan pengguna.
  • Produk, carian, kategori, stok, troli, dan pesanan.
  • Tugasan pekerja, komen, aktiviti, dan pertukaran status.
  • Pesanan manual daripada Shopee, TikTok, dan web.
  • Production, packaging, shipping, dan tracking.

Fail dan komunikasi

  • Upload artwork ke S3 melalui presigned URL.
  • Folder, share link, ZIP download, dan review artwork.
  • Redis cache dan Pub/Sub untuk kemas kini.
  • Socket.IO untuk maklumat masa nyata.
  • WhatsApp, Expo notification, chat, dan audit log.
  • EasyParcel quotation, AWB, webhook, dan cron tracking.

Worktree / Pokok Sistem

Fail Backend Duduk Di Mana?

Rajah ini ialah peta folder backend. Setiap folder mempunyai tugas yang berbeza.

backend/src/ |-- settings/ # hidupkan aplikasi dan server |-- presentation/ # pintu HTTP | |-- routes/ # senarai alamat API | |-- controllers/ # terima dan jawab request | `-- middlewares/ # auth, error, audit |-- application/ # peraturan perniagaan | |-- usecases/orders/ # cipta dan gerak pesanan | |-- usecases/cart/ # operasi troli | `-- usecases/user/ # login dan pengguna |-- domain/ # bentuk entiti sistem |-- infrastructure/ # sambungan dunia luar | |-- db/models/ # bentuk dokumen MongoDB | |-- db/repositories/ # baca dan simpan data | |-- services/ # EasyParcel, WhatsApp | |-- socket/ # kemas kini masa nyata | `-- jobs/ # kerja automatik cron `-- shared/ # utiliti yang dikongsi

Apa berlaku ketika pesanan dibuat?

  1. Backend membaca troli MongoDB pengguna.
  2. Backend mencari setiap produk dan saiz.
  3. Backend memeriksa stok dan mengurangkan stok.
  4. Backend mengira semula harga.
  5. Backend mencipta pesanan COD dengan status PLACED.
  6. Backend mencipta notifikasi dan tugasan pekerja.
  7. Backend mengosongkan troli dan cache berkaitan.
  8. Pekerja menggerakkan tugasan melalui artwork, design, printing, dan packaging.
  9. EasyParcel membuat shipment apabila syarat bayaran dan production dipenuhi.
  10. Webhook dan cron mengemas kini tracking sehingga DELIVERED.

Pepijat Dan Risiko

Apa Yang Rosak Atau Berbahaya?

TahapMasalahPenerangan paling mudah
KritikalKebenaran route tidak cukupPengguna yang sudah login boleh mencapai beberapa operasi pesanan, tugasan, chat, dan folder tanpa semakan pemilik atau peranan yang konsisten.
KritikalRoute ubah data terbukaRoute seed produk dan migration status boleh mengubah data tanpa authentication.
KritikalRahsia dalam GitFail deployment dan arkib environment mengandungi nilai sensitif. Rahsia perlu ditukar dan dibuang daripada sejarah.
TinggiStok tidak transactionalStok dikurangkan sebelum pesanan selesai. Jika langkah seterusnya gagal, stok boleh berkurang tanpa pesanan.
TinggiCOD menghalang shippingPesanan web bermula sebagai PENDING, tetapi shipment memerlukan PAID. Laluan biasa untuk menandakan bayaran tidak jelas.
TinggiQuery status guna medan salahKod mencari status, tetapi model menyimpan orderStatus.
TinggiSocket boleh menyamarSocket pelanggan mempercayai ID pengguna dalam query tanpa pengesahan JWT seperti socket admin.
TinggiCORS terlalu terbukaSemua origin diterima walaupun credentials digunakan. Webhook WhatsApp juga tidak memeriksa tandatangan.
SederhanaCache status lamaSenarai status boleh menunjukkan data lama sehingga 24 jam.
SederhanaArtwork dipadam ketika deliveredMenukar status kepada DELIVERED memadam fail berkaitan secara kekal.
SederhanaTiada test automatikFrontend dan backend tidak mempunyai suite ujian penuh untuk mengesan kerosakan.

Apa perlu dibuat selepas ini?

  1. Paling awal: tukar semua rahsia yang pernah dimasukkan ke Git.
  2. Gunakan pemeriksaan peranan untuk admin dan pemeriksaan pemilik untuk pelanggan pada setiap route.
  3. Jadikan semakan stok, pengurangan stok, dan penciptaan pesanan sebagai satu transaksi MongoDB.
  4. Tetapkan peraturan jelas untuk COD, PAID, dan bila EasyParcel boleh digunakan.
  5. Betulkan query status kepada orderStatus dan invalidasi cache status lama.
  6. Tambah ujian API dari login, troli, order, artwork, production, shipping, sehingga delivered.
Kesimpulan mudah: backend mempunyai banyak kuasa dan ciri operasi. Oleh sebab itu, kawalan keselamatan dan ketepatan transaksi perlu dibaiki sebelum menambah lebih banyak ciri baru.
